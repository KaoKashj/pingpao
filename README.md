# 选课约束筛选工具

把浙江大学本科教务（[zdbk.zju.edu.cn](https://zdbk.zju.edu.cn)）里难以人工排查的课程数据，
按「我要修的课程类别 + 我有空的时段 + 教师的评价门槛」整理成可筛选的表格。

> 数据快照：**2026–2027 学年第 1 学期**（采集于第二轮选课截止前）。
> 余量、容量、开课时间均为该时刻状态，**请以教务网为准**。

---

## 两种可能的形态（以及我为什么选 A）

这类工具存在两种完全不同的架构，差别不在技术难度，而在**一个原则问题：谁来持有凭据**。

| | **A · 缓存版（本项目采用）** | **B · 实时版** |
|---|---|---|
| 数据获取 | **你自己在本机跑一次**抓取 | 服务器替你实时抓 |
| 凭据在哪 | **你自己的机器上**（环境变量或本地文件） | **上传到我的服务器** |
| 部署形态 | 静态页面（Netlify / 本地文件） | 需要常驻后端服务 |
| 数据新鲜度 | 抓取那一刻的快照 | 每次访问都是最新 |
| 谁能用 | 会跑命令的人 | 任何人打开网页 |
| 维护成本 | ≈0 | 服务器 + 会话管理 + 限流 |

### 为什么我没有做 B

实时版在技术上完全可行，但它要求**用户把教务系统的账号密码交给我**——我需要替每个用户维持登录会话，
才能以他的身份去请求教务系统。这会同时带来三个问题：

1. **安全**：我成了「保管大量同学教务密码」的人。一旦服务器被入侵或我本人失误，
   后果不可承受，而且**任何技术优化都无法弥补**。
2. **合规**：以他人身份访问学校系统，属于**冒用身份**。学校对统一身份认证账号有明确规定
   （不得转借、代他人操作）。这不是「我保证不乱搞」能解决的——**问题不在于我会不会乱来，
   而在于这种结构本身就不该存在**。
3. **对教务系统的压力**：实时版意味着每个用户每次访问都要发出几十次请求
   （因为「课程目录不含上课时间」，必须按课程号逐门查教学班）。
   在选课高峰期，这是对全校共用的教务系统做放大攻击。

**一个有说服力的旁证**：求是潮自己的 [Enroll_nx](https://github.com/QSCTech/Enroll_nx) 是
**浏览器插件**形态——跑在用户自己的浏览器里、用用户自己的登录态，
**密码从不经过他们的服务器**。插件形态在校园工具里如此常见，正是为了绕开这个凭据问题。

**所以我选 A**：让每个人在自己的机器上、用自己的凭据跑一次，
数据实时性由使用者自己保证，**凭据永远不离开本人**。这份仓库因此可以安全公开。

> 换句话说：**A 不是 B 的简化版，而是对同一个需求给出的、边界更清楚的答案。**

### B 在什么情况下才合理

只有当**使用者本人就是服务提供者**时才成立——比如你自己搭一台服务器，
只抓你自己的数据、只给你自己看。一旦服务对象变成「别人」，凭据问题就必然出现。

## ⚠️ 运行前提：本仓库依赖一个外部登录模块

**直接 `python probe_scan.py` 会失败。** 本项目里 8 个脚本需要访问教务系统，而登录逻辑**不在本仓库内**——
它们通过 `importlib` 从本机加载一个独立模块：

```python
# 每个联网脚本开头都是这段
spec = importlib.util.spec_from_file_location(
    "zju_jwglxt", "~/.codex/skills/zju-jwglxt/scripts/zju_jwglxt.py")
```

### 两类数据：一类要联网抓，一类读本地

| 数据 | 来源 | 要登录吗 | 会不会变 |
|---|---|---|---|
| 课程目录 | 教务网 `zzxkghb_cxZzxkGhbKcList` | ✅ | 每学期变 |
| 上课时间 / 余量 / 容量 | 教务网 `zzxkghb_cxZzxkGhbJxbList`（**按课程号逐个查**） | ✅ | **随时在变** |
| 培养方案课程清单 | 本地 PDF 解析 | ❌ | 基本不变 |
| 教师评价 | 第三方平台 | ❌ | 缓慢变化 |

**取数层（要登录、要联网）→ 缓存层（落盘的快照）→ 展示层（纯静态、永不联网）**，
三层是分离的：一旦快照生成，后面所有环节（Excel、Markdown、网页）都只读本地文件。

> 这也是为什么网页能部署在静态托管上：**它消费的是快照，不是实时数据。**

### 为什么必须登录（这不是可选项）

教务系统的数据接口**全部在登录态之后**，没有匿名入口：

| 数据 | 从哪来 | 要登录吗 |
|---|---|---|
| 课程目录 | `zzxkghb_cxZzxkGhbKcList` | ✅ |
| 上课时间 / 余量 / 容量 | `zzxkghb_cxZzxkGhbJxbList`（**按课程号逐个查**） | ✅ |
| 培养方案课程清单 | 本地 PDF 解析 | ❌ |
| 教师评价 | 第三方平台 | ❌ |

两个关键约束：

1. **课程目录不含上课时间**。要知道「某门课周几上、还剩多少名额」，必须**按课程号逐门查教学班**——
   这意味着查 50 门课就要发 50 次带登录态的请求。凭据是每次请求都在用的，不是「进门用一次」。
2. **数据是活的**。余量、容量随时变动。所以本项目产出的永远是**某一时刻的快照**
   （线上页面标注：采集于 2026.9.10 第二轮选课截止前），而不是实时数据。

**那网页为什么不用登录？** 因为网页是**纯静态页面**，读的是已经爬好的快照
（`窗口时段课程结果_明细.tsv` 内嵌进 HTML），部署在静态托管上，不访问教务系统。

### 为什么把登录拆成独立模块

它要处理浙大统一身份认证（CAS SSO）与 RSA 密码加密，和「选课数据整理」是两件不同的事；
拆开后本仓库可以安全公开，**账号密码永远不进版本控制**。

### 在你自己的机器上跑起来

**第 1 步：准备登录模块**

需要一个 `zju_jwglxt.py`，对外暴露：

```python
def get_credentials():                 # 返回 (username, password)
class Jwglxt:
    def __init__(self, username, password): ...
    def login(self) -> bool: ...
    def req(self, url, data=None, referer=None): ...
    def course_context(self): ...       # 返回 (ctx, categories)
```

自带的凭据读取顺序（**不用改代码，把凭据放对位置即可**）：

1. 环境变量 `ZJU_JWGLXT_USERNAME` / `ZJU_JWGLXT_PASSWORD`
2. 文件 `~/.config/zju-jwglxt/credentials.json`，内容 `{"username": "...", "password": "..."}`

**第 2 步：用环境变量指向你的路径**（不用改代码）

所有路径集中在 `config.py`，用环境变量覆盖即可：

```bash
export ZJU_JWGLXT_MODULE=/你的路径/zju_jwglxt.py          # 登录模块
export COURSEFIT_PDF=/你的路径/2026级XXX专业培养方案.pdf   # 培养方案 PDF
export COURSEFIT_PROJECT=~/coursefit                      # 输出目录（可选）
```

| 变量 | 作用 | 默认值 |
|---|---|---|
| `ZJU_JWGLXT_MODULE` | 登录模块路径 | `~/.codex/skills/zju-jwglxt/scripts/zju_jwglxt.py` |
| `COURSEFIT_PDF` | 培养方案 PDF | 空（**必须指定**） |
| `COURSEFIT_PROJECT` | 产物输出目录 | `~/Documents/ChatGPT/选课` |
| `COURSEFIT_TMP` | 中间产物目录 | 系统临时目录下的 `coursefit/` |

找不到模块或 PDF 时，脚本会**打印可操作的提示**（告诉你要设哪个变量），而不是抛一个看不懂的异常。

**第 3 步：装依赖**

```bash
pip install pdfplumber openpyxl
```

**第 4 步：配置凭据**（二选一）

```bash
# 方式 A：环境变量
export ZJU_JWGLXT_USERNAME='你的学号'
export ZJU_JWGLXT_PASSWORD='你的密码'

# 方式 B：配置文件
mkdir -p ~/.config/zju-jwglxt
printf '{"username":"你的学号","password":"你的密码"}' > ~/.config/zju-jwglxt/credentials.json
chmod 600 ~/.config/zju-jwglxt/credentials.json
```

> 🔒 `.gitignore` 已排除 `credentials*.json` 与 `.env*`，**密码不会进仓库**。

**第 5 步：跑**

```bash

python extract_courses_final.py  # 从培养方案 PDF 提取课程
python friday_sweep.py           # 查教学班时间与余量
python make_excel.py             # 生成 Excel
```

## Problem · 为什么做这个

选课的时候，教务网能回答「有哪些课」，但回答不了我真正要判断的三件事：

| 我要判断的 | 答案在哪 |
|---|---|
| 这门课是不是我**必须修**的类别？ | 培养方案 PDF（**不在**教务网） |
| 这个班的时间和我的**空闲时段**冲不冲突？ | 「教学班」接口（**列表页看不到**） |
| 这个**老师**讲课怎么样？ | 第三方评价平台 |

三件事分属三个地方，只能靠人一个个点开对照。每学期都要做一遍，所以我想自动化一次。

## Method · 怎么做的

### 关键认知：先探测，再固化

教务系统没有公开 API，也没有文档。我一开始完全不知道该请求哪个地址、会返回什么结构。

所以流程是：**先写一次性探测脚本把接口摸清楚，再把「最快能跑通的那条路径」固化成正式流程。**

如果一开始就照着猜的结构写正式脚本，后面每发现一处猜错就要改一遍。

### 一个具体的坑

课程目录接口（`zzxkghb_cxZzxkGhbKcList`）只返回「课程头」，**不含上课时间**。

上课时间、余量、容量全在**另一个**「教学班」接口（`zzxkghb_cxZzxkGhbJxbList`）里，
而且必须**按课程代码逐个查询**。字段 `sksj` 是类似 `周五第3,4节{单周}` 的文本，多时段用 `<br>` 分隔。

这意味着「查某天有哪些课」不能一次请求解决——先拿全量目录，再对每门课查一次教学班。
这个认知直接决定了数据流怎么设计。

### 第二个坑：培养方案 PDF 抽不出文本

这类 PDF 的正文上叠了**水印单字**（来自「浙江大学」和它的反写 `ytisrevnUgnaijehZ`），散落在页面各处。

直接用 `extract_text()`，水印的字会混进表格，把每一行的列位置全打乱。

**解法**：不按「文本流」抽，而是**按坐标把字重建回行**，再滤掉「单独成词的水印单字」：

```python
WATERMARK = set("ytisrevnUgnaijehZ浙江大学")
# 只滤「单独成词」的水印字——已连成词组的不能滤
ws = [w for w in words if not (len(w["text"]) == 1 and w["text"] in WATERMARK)]
ws.sort(key=lambda w: (round(w["top"] / 4.0), w["x0"]))   # 按 top 分桶成行，行内按 x0 排序
```

> 「抽不出文本」看起来是工具问题，其实是**数据问题**——换个思路（从文本流换成坐标）才有解。

### 数据流

```
培养方案 PDF ──extract_pdf──▶ 原始文本
             ──extract_courses_final──▶ 培养方案课程清单.tsv
                                              │
zdbk 选课目录 ──scan_catalog──▶ 候选课程池 ────┤
                                              ▼
                                  find_friday / friday_sweep
                                              │  逐课查教学班，取上课时间/余量/教师
                                              ▼
                                    结果 TSV ──make_excel──▶ Excel
```

**三个数据源的粒度不同**，这是设计里最容易出错的地方：

| 来源 | 粒度 | 关键字段 |
|---|---|---|
| 教务网课程目录 | 一门课 | 课程号、课程名、开课学院 |
| 教务网教学班 | 一门课的**一个班** | 教学班号、教师、上课时间、余量、容量 |
| 培养方案 PDF | 培养方案里的一条 | 课程号、课程类别 |
| 第三方评价 | 一位**教师** | 教师名、评分 |

所以最终**以课程号为主干，把教学班展开成多行**（同一门课可能有多个班、多个老师、多个时间），
再挂上培养方案里的类别，最后按教师名把评价接进来。

## 文件说明

### 探查层（一次性的侦察脚本，用于摸清接口结构）

| 文件 | 干什么 |
|---|---|
| `probe_scan.py` | 扫描 zdbk 选课分类，dump 开课数据到 `/tmp`，看有哪些字段 |

### 流水线

| 文件 | 输入 → 输出 |

### Results · 结果

- 本学期候选中，按个人窗口筛出 **25 门**可排课程（PDF 培养方案 16 门、通识选修 9 门）

## Limitations · 我知道它哪里脆弱

1. **不能开箱即用**（见文首警告）：登录模块不在仓库内，clone 后需自备模块并设置
   `ZJU_JWGLXT_MODULE` / `COURSEFIT_PDF`。这是**有意为之**——为了让凭据永不进版本控制。
2. **数据源是脆的**。教务网没有公开 API，接口结构一旦改版，抓取层就失效。
   因此「抓取」与「处理/展示」是分离的两层——**抓取失败不影响已生成的结果页**。
3. **教师评价来自第三方平台**，不是官方数据，且会变化，仅作参考。
4. **余量/容量是抓取那一刻的快照**，随时变动。
5. **筛选条件是个人口径**（我的空闲窗口、我要修的课程类别），不是通用配置，别人拿去不一定适用。
6. **依赖外部模块**：多数脚本通过 `importlib` 动态加载
   `~/.codex/skills/zju-jwglxt/scripts/zju_jwglxt.py`（统一身份认证登录 zdbk）。
   **换台机器 clone 下来无法直接运行**，需要先具备该模块，或把登录逻辑内联进来。
7. **尚未自动化**：换学期需要手动重跑流程，没有定时任务。

## Learned · 学到的东西

- **先探测再固化**：面对没有文档的系统，写一次性探测脚本的成本远低于反复猜错。
- **数据问题看起来像工具问题**：PDF「抽不出文本」的解法不是换工具，而是换思路（文本流 → 坐标）。
- **主动标注口径**：产物的 `.md` 头部写清筛选条件与剔除规则，让结果可复现、可追溯。
- **把重复步骤沉淀成可复用流程**：摸清接口后固化，换学期重跑不需要重新摸索。
- **凭据与代码分离**：把登录模块拆出仓库，是本项目能公开的前提。
- **可移植性要在设计时就考虑**：绝对路径让这份代码只能在一台机器上跑，是明显的返工点；
  后来把路径收敛到 `config.py`，才做到「换机器只设环境变量」。
- **凭据边界决定架构**：能不能做「实时版」，卡点不在技术，而在**要不要持有别人的密码**。

## 说明

- 本项目仅用于**个人选课参考**：只读取教务系统的公开页面，**不传播数据、不做自动抢课或自动提交**。
- 仓库中**不含**任何个人选课状态、账号或身份信息。

## 如何为下一学期重新生成

1. 确认教务账号会话有效（`zju-jwglxt` 模块）
2. 重跑 `scan_catalog.py` 取最新课程目录；**期间留意接口结构有无变化**
