# 选课约束筛选工具

把浙大教务 zdbk 里那些很难人工排查的课程数据，按「我要修的课程类别 + 我有空的时段 +
教师评价门槛」整理成一张能筛选的表格。数据是 2026–2027 学年第 1 学期的（第二轮选课截止前抓的），
余量和容量以教务网为准。

## 这个仓库有两种用法

只想看结果 —— 直接打开 `index.html`（双击就行），或者访问线上地址
<https://zju-coursefit-pingpao.netlify.app>。不用登录，不用装东西，不用跑脚本；
网页是纯静态的，数据内嵌在里面，不联网。

想自己更新数据（换学期了，或者想改筛选条件）—— 见文末「自己重新生成数据（可选）」。
那一步要用到你自己的教务账号，但账号只在你自己电脑上用，不会上传到任何地方。

## 为什么写这个

选课的时候，教务网能回答「有哪些课」，但回答不了我真正要判断的三件事：

| 我要判断的 | 答案在哪 |
|---|---|
| 这门课是不是我必须修的类别？ | 培养方案 PDF（不在教务网） |
| 这个班的时间和我的空闲时段冲不冲突？ | 「教学班」接口（列表页看不到） |
| 这个老师讲课怎么样？ | 第三方评价平台 |

三件事分属三个地方，只能靠人一个个点开对照。每学期都要做一遍，所以我想自动化一次。

## 怎么做的

### 先探接口，再写代码

教务系统没有公开 API，也没有文档。我一开始完全不知道该请求哪个地址、会返回什么结构。

所以流程是：先写一次性探测脚本把接口摸清楚，再把「最快能跑通的那条路径」固化成正式流程。

如果一开始就照着猜的结构写正式脚本，后面每发现一处猜错就要改一遍。

### 上课时间不在课程目录里

课程目录接口（`zzxkghb_cxZzxkGhbKcList`）只返回「课程头」，不含上课时间。

上课时间、余量、容量全在另一个「教学班」接口（`zzxkghb_cxZzxkGhbJxbList`）里，
而且必须按课程代码逐个查询。字段 `sksj` 是类似 `周五第3,4节{单周}` 的文本，多时段用 `<br>` 分隔。

这意味着「查某天有哪些课」不能一次请求解决——先拿全量目录，再对每门课查一次教学班。
这个认知直接决定了数据流怎么设计。

### PDF 抽不出能用的文本

这类 PDF 的正文上叠了水印单字（来自「浙江大学」和它的反写 `ytisrevnUgnaijehZ`），散落在页面各处。

直接用 `extract_text()`，水印的字会混进表格，把每一行的列位置全打乱。

解法：不按「文本流」抽，而是按坐标把字重建回行，再滤掉「单独成词的水印单字」：

```python
WATERMARK = set("ytisrevnUgnaijehZ浙江大学")
# 只滤「单独成词」的水印字——已连成词组的不能滤
ws = [w for w in words if not (len(w["text"]) == 1 and w["text"] in WATERMARK)]
ws.sort(key=lambda w: (round(w["top"] / 4.0), w["x0"]))   # 按 top 分桶成行，行内按 x0 排序
```

> 「抽不出文本」看起来是工具问题，其实是数据问题——换个思路（从文本流换成坐标）才有解。

### 几个脚本的关系

这些脚本不是一个自动跑的管道，是我按顺序手动执行的几个步骤，顺序不能乱：

```
培养方案 PDF ──extract_pdf──▶ 原始文本
             ──extract_courses_final──▶ 培养方案课程清单.tsv
131 份培养方案 PDF ──build_kb.py──▶ kb.json
                                              │
zdbk 选课目录 ──scan_catalog──▶ 候选课程池 ────┤
                                              ▼
                                  fetch_sections.py
                                              │  逐课查教学班，取上课时间/余量/教师
                                              ▼
                                    结果 TSV ──make_excel──▶ Excel
```

三个数据源的粒度不同，这是设计里最容易出错的地方：

| 来源 | 粒度 | 关键字段 |
|---|---|---|
| 教务网课程目录 | 一门课 | 课程号、课程名、开课学院 |
| 教务网教学班 | 一门课的一个班 | 教学班号、教师、上课时间、余量、容量 |
| 培养方案 PDF | 培养方案里的一条 | 课程号、课程类别 |
| 第三方评价 | 一位教师 | 教师名、评分 |

所以最终以课程号为主干，把教学班展开成多行（同一门课可能有多个班、多个老师、多个时间），
再挂上培养方案里的类别，最后按教师名把评价接进来。

## 为什么不做实时版

这类工具存在两种完全不同的架构，差别不在技术难度，而在一个原则问题：谁来持有凭据。

| | A · 缓存版（本项目采用） | B · 实时版 |
|---|---|---|
| 数据获取 | 你自己在本机跑一次抓取 | 服务器替你实时抓 |
| 凭据在哪 | 你自己的机器上（环境变量或本地文件） | 上传到我的服务器 |
| 部署形态 | 静态页面（Netlify / 本地文件） | 需要常驻后端服务 |
| 数据新鲜度 | 抓取那一刻的快照 | 每次访问都是最新 |
| 谁能用 | 会跑命令的人 | 任何人打开网页 |
| 维护成本 | ≈0 | 服务器 + 会话管理 + 限流 |

### 实时版的问题在哪

实时版在技术上完全可行，但它要求用户把教务系统的账号密码交给我——我需要替每个用户维持登录会话，
才能以他的身份去请求教务系统。这会同时带来三个问题：

1. 安全：我成了「保管统一身份认证密码」的人。一旦服务器被入侵或我本人失误，
   后果不可承受，而且任何技术优化都无法弥补。
2. 合规：以他人身份访问学校系统，属于冒用身份。学校对统一身份认证账号有明确规定
   （不得转借、代他人操作）。这不是「我保证不乱搞」能解决的——问题不在于我会不会乱来，
   而在于这种结构本身就不该存在。

所以我选 A：让每个人在自己的机器上、用自己的凭据跑一次，
数据实时性由使用者自己保证，凭据永远不离开本人。这份仓库因此可以安全公开。

## 已知问题

1. 不能开箱即用（见文首警告）：登录模块不在仓库内，clone 后需自备模块并设置
   `ZJU_JWGLXT_MODULE` / `COURSEFIT_PDF`。这是有意为之——为了让凭据永不进版本控制。
2. 数据源是脆的。教务网没有公开 API，接口结构一旦改版，抓取层就失效。
   因此「抓取」与「处理/展示」是分离的两层——抓取失败不影响已生成的结果页。
3. 教师评价来自第三方平台，不是官方数据，且会变化，仅作参考。
4. 余量/容量是抓取那一刻的快照，随时变动。
5. 筛选条件是个人口径（我的空闲窗口、我要修的课程类别），不是通用配置，别人拿去不一定适用。
6. 依赖外部模块：多数脚本通过 `importlib` 动态加载
   `~/.codex/skills/zju-jwglxt/scripts/zju_jwglxt.py`（统一身份认证登录 zdbk）。
   换台机器 clone 下来无法直接运行，需要先具备该模块，或把登录逻辑内联进来。
7. 尚未自动化：换学期需要手动重跑流程，没有定时任务。

## 做完之后的几点想法

- 先探测再固化：面对没有文档的系统，写一次性探测脚本的成本远低于反复猜错。
- 数据问题看起来像工具问题：PDF「抽不出文本」的解法不是换工具，而是换思路（文本流 → 坐标）。
- 主动标注口径：产物的 `.md` 头部写清筛选条件与剔除规则，让结果可复现、可追溯。
- 把重复步骤沉淀成可复用流程：摸清接口后固化，换学期重跑不需要重新摸索。
- 凭据与代码分离：把登录模块拆出仓库，是本项目能公开的前提。
- 可移植性要在设计时就考虑：绝对路径让这份代码只能在一台机器上跑，是明显的返工点；
  后来把路径收敛到 `config.py`，才做到「换机器只设环境变量」。
- 凭据边界决定架构：能不能做「实时版」，卡点不在技术，而在要不要持有别人的密码。

## 使用边界

- 本项目仅用于个人选课参考：只读取教务系统的公开页面，不传播数据、不做自动抢课或自动提交。
- 仓库中不含任何个人选课状态、账号或身份信息。

## 自己重新生成数据（可选）

如果你只是想看结果，这一整节可以跳过 —— 网页不依赖这里的任何东西。

这一节给的是：数据过期了、或者你想改筛选条件时，怎么重新生成一份。

直接 `python probe_scan.py` 会失败。 本项目里 8 个脚本需要访问教务系统，而登录逻辑不在本仓库内——
它们通过 `importlib` 从本机加载一个独立模块：

```python
# 每个联网脚本开头都是这段
spec = importlib.util.spec_from_file_location(
    "zju_jwglxt", "~/.codex/skills/zju-jwglxt/scripts/zju_jwglxt.py")
```


### 怎么跑

第 1 步：准备登录模块

需要一个 `zju_jwglxt.py`，对外暴露：

```python
def get_credentials():                 # 返回 (username, password)
class Jwglxt:
    def __init__(self, username, password): ...
    def login(self) -> bool: ...
    def req(self, url, data=None, referer=None): ...
    def course_context(self): ...       # 返回 (ctx, categories)
```

自带的凭据读取顺序（不用改代码，把凭据放对位置即可）：

1. 环境变量 `ZJU_JWGLXT_USERNAME` / `ZJU_JWGLXT_PASSWORD`
2. 文件 `~/.config/zju-jwglxt/credentials.json`，内容 `{"username": "...", "password": "..."}`

第 2 步：用环境变量指向你的路径（不用改代码）

所有路径集中在 `config.py`，用环境变量覆盖即可：

```bash
export ZJU_JWGLXT_MODULE=/你的路径/zju_jwglxt.py          # 登录模块
export COURSEFIT_PDF=/你的路径/2026级XXX专业培养方案.pdf   # 培养方案 PDF
export COURSEFIT_PROJECT=~/coursefit                      # 输出目录（可选）
```

| 变量 | 作用 | 默认值 |
|---|---|---|
| `ZJU_JWGLXT_MODULE` | 登录模块路径 | `~/.codex/skills/zju-jwglxt/scripts/zju_jwglxt.py` |
| `COURSEFIT_PDF` | 培养方案 PDF | 空（必须指定） |
| `COURSEFIT_PROJECT` | 产物输出目录 | `~/Documents/ChatGPT/选课` |
| `COURSEFIT_TMP` | 中间产物目录 | 系统临时目录下的 `coursefit/` |

找不到模块或 PDF 时，脚本会打印可操作的提示（告诉你要设哪个变量），而不是抛一个看不懂的异常。

第 3 步：装依赖

```bash
pip install pdfplumber openpyxl
```

第 4 步：配置凭据（二选一）

```bash
# 方式 A：环境变量
export ZJU_JWGLXT_USERNAME='你的学号'
export ZJU_JWGLXT_PASSWORD='你的密码'

# 方式 B：配置文件
mkdir -p ~/.config/zju-jwglxt
printf '{"username":"你的学号","password":"你的密码"}' > ~/.config/zju-jwglxt/credentials.json
chmod 600 ~/.config/zju-jwglxt/credentials.json
```

>  `.gitignore` 已排除 `credentials*.json` 与 `.env*`，密码不会进仓库。

第 5 步：跑

```bash
python scan_catalog.py           # 取课程目录
python extract_courses_final.py  # 从培养方案 PDF 提取课程
python fetch_sections.py         # 查教学班时间与余量
python make_excel.py             # 生成 Excel
```

### 换机器怎么改路径

已完成：原先 12 个脚本各自硬编码绝对路径，现已全部收敛到 `config.py`，
用环境变量覆盖即可移植，不需要改任何代码。

- 只读取公开页面，不做自动抢课、不传播数据
- 中间产物默认写到系统临时目录，可用 `COURSEFIT_TMP` 改到项目内

## 换学期时的完整步骤

1. 确认教务账号会话有效（`zju-jwglxt` 模块）
2. 重跑 `scan_catalog.py` 取最新课程目录；期间留意接口结构有无变化
3. 重跑 `extract_courses_final.py` 从最新培养方案 PDF 提取课程清单
4. 重跑 `fetch_sections.py` 查教学班时间与余量
5. 更新第三方评价数据并合并
6. `make_excel.py` 生成表格
